# Security

Threat model for the sealed reverse-auction market contract (`contract/`, `near-sdk` 5).
Every defense below is linked to a test that proves it. Run the on-chain-logic tests with:

```
cd contract && cargo test --lib --offline
```

(38 tests, all green). The sandbox integration tests live in `contract/tests/`.

## Assumptions

- **Limited FunctionCall keys.** Agents and the verifier operate with NEAR FunctionCall
  access keys restricted to this contract and the methods they need, with a finite gas
  allowance. No full-access keys are used for day-to-day operation.
- **Commit–reveal bidding.** A bid is committed as `sha256(price || salt || account)` and
  revealed in a later window. Prices are hidden until the commit window closes, so a worker
  cannot undercut a price it was not able to see.
- **Per-agent spend cap.** Each worker has a cumulative payout cap (`cap_per_agent_yocto`).
  Settlement that would exceed the remaining cap is refused and the escrow is refunded.
- **Single configured verifier per task.** Only the account the task author designates as
  verifier can attest the result and trigger settlement or refund.

## Threats and defenses

| Threat | Contract defense | Test evidence (`contract/`) |
|---|---|---|
| **Worker keeps the escrow without delivering accepted work** | Only the round winner may submit a result, and only the configured verifier decides settlement. Failed attestations and expired tasks refund the escrow; escrow is conserved across every settlement and refund path. | `submit_result_requires_a_closed_round_won_by_the_caller`, `only_winner_can_submit_result_once`, `verifier_attestation_settles_once_and_updates_reputation`, `failed_attestation_refunds_and_lowers_reputation`, `expired_refund_requires_grace_and_penalizes_missing_result`, `settlements_and_refunds_conserve_the_escrow` — `src/lib.rs` |
| **Fake or altered bid** | Commitments must be SHA-256 hashes; only the committing worker may reveal, and the revealed data must match the commitment and fall inside its window. | `rejects_commitments_that_are_not_sha256_hashes`, `only_committing_worker_can_reveal_a_bid`, `rejects_reveal_that_does_not_match_commitment`, `rejects_commit_and_reveal_outside_their_windows` — `src/lib.rs` |
| **Verifier impersonation** | `attest` checks the caller against the task's configured verifier before changing any state, reputation, or escrow. | `rejects_attestation_from_a_non_verifier_account`, `verifier_attestation_settles_once_and_updates_reputation` — `src/lib.rs` |
| **Spending beyond the per-agent cap** | Settlement is refused and escrow refunded when the remaining cap is insufficient; spend is tracked cumulatively, and the boundary case pays exactly up to the limit. | `cap_exceeded_refunds_instead_of_paying`, `cap_boundary_pays_up_to_limit_and_refunds_when_payment_exceeds_remaining` — `src/lib.rs` |
| **Storage griefing / frozen escrow** | Every caller-supplied string stored in state is length-bounded, so an attacker running a 1-yocto task of its own cannot bloat contract storage with a huge `result_hash` (≤128 B) or task `id` (≤64 B) and push the contract's free balance below its storage stake, which would otherwise freeze honest escrows (`LackBalanceForState` on `attest`/`refund_expired`). | `test_storage_griefing_freezes_honest_escrow` — `tests/test_storage_griefing.rs` |
| **Round-spam storage griefing / frozen escrow** | `post_task` enforces a storage-reserve invariant: the contract's own funds (balance minus the escrows it still owes) must cover its staked storage plus a fixed reserve. A burst of many distinct 1-yocto tasks grows staked storage faster than its escrows, so each spam task is rejected (`Storage reserve exhausted`) before the free balance can drop below the storage stake and freeze an honest payout with `LackBalanceForState`. No state-layout change (upgradeable without migration). | `distinct_minimum_deposit_rounds_cannot_freeze_honest_payout` — `tests/test_round_spam.rs` |
| **Collusive verifier / Sybil reputation pump** | Reputation is Beta(α,β) evidence, not an identity claim: one operator controlling publisher, worker, and verifier can run self-dealing rounds to raise its own α at only gas cost, and a pumped Sybil can win over a cheaper honest worker because the price is divided by the mean Beta score. This is a disclosed design limit, not a contract bug — the on-chain rules (fixed verifier per task, escrow conservation, per-agent cap) still hold; defending against identity farming requires off-chain Sybil resistance (staking, KYC, or a trusted verifier set). The tests pin the exact cost and effect so the limit cannot silently widen. | `collusive_verifier_pumps_reputation_at_near_zero_cost`, `pumped_sybil_outbids_a_cheaper_honest_worker`, `control_without_pump_the_cheaper_honest_worker_wins` — `tests/test_collusive_verifier_reputation.rs` |
| **Selective reveal (Sybil bid ladder)** | Commit-reveal has no bid bond, so a commitment is a free option. One operator commits a ladder of sealed prices from Sybil accounts (10..90); reveals are public during the window, so after the honest worker reveals 55 it reveals only the rung at 50, wins at the highest price that still undercuts, and abandons the other 8 commitments with no slash and Beta untouched. Disclosed design limit: winner and escrow rules still hold and the publisher never pays above the reward. Honest-side mitigation: reveal in the last block of the window (a same-block reveal cannot be observed first); protocol fix needs a per-commit bond slashed on non-reveal (state-layout change, deferred). | `ladder_operator_reveals_only_the_rung_under_the_honest_price`, `abandoned_rungs_cost_nothing` — `contract/tests/test_selective_reveal_ladder.rs` |
| **Stolen function-call key** | Restrict the key to this contract and the required methods, set a finite gas allowance, and revoke it promptly if compromised. **Documented gap:** if the stolen key is authorized for `attest`, it can still release escrow after a winner submits a result — the contract cannot distinguish it from the legitimate verifier. This is an operational risk, not a contract defense: no test can prove key scope, allowance, or revocation, which are enforced off-chain. What is pinned is that the contract never *widens* that scope itself — it manages no access keys, exposes no owner/migration backdoor, and the task verifier is fixed at `post_task` and never reassigned, so a stolen worker key cannot escalate. | `contract_never_manages_access_keys`, `contract_has_no_owner_or_migration_backdoor`, `task_verifier_is_immutable_after_post_task`, `escrow_only_leaves_via_transfer` — `tests/test_key_scope.rs` |
| **Broken upgrade / state loss on redeploy** | The live testnet account is upgraded by redeploying the same-layout wasm with no init call (the `LISTO-DEPLOY` path). A bad upgrade could reset the singleton, drop collections, or require a migration that corrupts in-flight escrows. The contract keeps a fixed state layout (same structs and storage keys), so redeploying the same wasm without an init call preserves every task, registered worker, open bid, and Beta reputation, and an in-flight round still settles on the upgraded code — no migration, no state reset. | `redeploy_same_layout_preserves_state_without_migration` — `tests/test_state_upgrade.rs` |
| **Gas-exhaustion DoS** | A function whose gas cost grows with state (unbounded loops over tasks/bids) could become uncallable once the market fills, freezing settlements. The storage-reserve guard once summed escrow over every stored task (~0.18 Tgas per task: 30 Tgas default exceeded at ~150 tasks, market bricked at ~1,650); it now reads a running open-escrow total kept under a raw storage key (no struct layout change, legacy state falls back to one scan), so guarded calls stay ~2.4 Tgas at 60 tasks (slope < 1 Ggas/task). Measured over a full lifecycle each call burns ≤ 3.3 Tgas (max `attest` 3.30, `refund_expired` 2.76, all others ~2.1–2.3), far under the 15 Tgas budget and the 30 Tgas default allowance, so no honest caller ever needs to raise gas. | `test_gas_per_function_within_budget` — `tests/test_gas_budget.rs`; `guard_gas_slope_per_stored_task` — `tests/test_guard_gas_scaling.rs` |
| **Open-task griefing / escrow freeze** | An attacker opens many cheap tasks at once to grow staked storage and starve an honest escrow of free balance. Because `post_task` charges the storage-reserve invariant per task, a 100-task spam burst is each priced in real funds and never pushes the contract below its storage stake, so an honest escrow still settles (`LackBalanceForState` cannot be triggered). | `minimum_deposit_open_task_spam_cannot_freeze_honest_escrow` — `tests/test_open_task_griefing.rs` |
| **Reputation laundering via re-registration** | A high Beta `β` from failed attests makes a worker look dear to the reverse auction (price is divided by mean Beta), so the cheapest single-account escape would be to call `register_worker` again and reset the history to the Beta(1,1) prior. `register_worker` rejects any already-registered account (`Worker already registered`) and never writes the `reputations` map, so accrued `β` cannot be wiped: a worker only clears a bad record by abandoning the account for a fresh one, i.e. the Sybil path already disclosed above. | `reregistration_is_rejected`, `bad_reputation_survives_reregistration_attempt` — `tests/test_reputation_laundering.rs` |
| **Double settlement (attest vs refund race)** | An escrow has two exits: `attest` by the verifier and `refund_expired` by anyone after the grace window. If both could fire for one task, the reward would be paid twice (to the worker and back to the publisher) out of other escrows. Both exits require `TaskState::Closed` and move the task to a terminal state (`Settled`/`Refunded`) before transferring, so the second exit is rejected (`Task is not closed`), the per-agent spend counter and Beta move exactly once, and a late `attest(true)` after a refund pays nothing. | `settled_task_cannot_be_refunded_or_paid_twice`, `refunded_task_cannot_be_attested_or_refunded_again` — `tests/test_settlement_exclusivity.rs` |
| **Sybil registration / commit storage griefing** | `register_worker` and `commit_bid` grow state but take no deposit, so Sybil accounts paying only gas could stake storage until it ate into owed escrows (`LackBalanceForState` on the honest payout; reproduced before the fix: invariant broken at the 10th registration / 7th commit with 0.03 NEAR own funds). Both now flush their writes and enforce the same storage-reserve invariant as `post_task`, so spam is rejected (`Storage reserve exhausted`) while escrows stay covered. No state-layout change. | `sybil_registrations_cannot_eat_into_owed_escrow`, `sybil_commits_cannot_eat_into_owed_escrow` — `tests/test_registration_spam.rs` |
| **Window off-by-one (bid peeking / cut reveals)** | If one block height admitted both commit and reveal, a bidder could read revealed prices and still commit; if `close_round` fired before `reveal_end`, honest reveals would be cut; a gap would make a round unclosable. Windows are half-open (`commit < commit_end <= reveal < reveal_end <= close`), so every height admits exactly one phase, and a bidder who withholds a cheaper reveal cannot reveal late, win or submit. | `phases_partition_the_timeline_with_no_overlap_or_gap`, `withheld_cheaper_bid_cannot_reveal_late_win_or_submit` — `tests/test_window_boundaries.rs` |
| **Bid flood freezes the round** | A task had no cap on sealed bids; `close_round` reads one reputation per bid (~77 Ggas/bid host-side, measured), so ~3.9k Sybil bids would push it past the 300 Tgas cap, and since `refund_expired` needs a Closed task the honest escrow would be frozen forever. `commit_bid` now rejects bids past `MAX_BIDS_PER_TASK` = 512 (one const + one `require!`, no layout change), keeping `close_round` at ~51 Tgas in the worst case (sandbox-measured 96 Ggas/bid, 4→36 bids 2.5→5.6 Tgas, extrapolated to 512; attach ≥60 Tgas, 300 Tgas only at ~3.1k bids); slot squatting can at worst deny one round, never lock funds. | `bid_flood_cannot_freeze_close_round`, `commit_past_bid_cap_is_rejected_and_round_still_settles_honestly` — `tests/test_close_round_many_bids.rs`; `close_round_gas_at_bid_cap_is_bounded` — `tests/test_close_round_gas_sandbox.rs` |
| **Oversized view response blanks the dashboard** | `list_tasks` capped the task count (100) but not the payload: 100 bid-flooded tasks (512 commitments + 512 bids, 64-char ids) serialise to 16.5 MB, above NEAR's 4 MiB `max_length_returned_data`, so the view failed and the web dashboard (`TASKS_LIMIT` = 100) went blank. `list_tasks` now stops a page at `MAX_LIST_ENTRIES` = 8,192 commitments+bids (worst page 1.3 MB; always returns at least one task, clients page with `from += len`; view-only, no layout change). | `contract/tests/test_list_tasks_return_size.rs` (`list_tasks_payload_fits_in_returned_data_limit`, `single_oversized_task_is_still_returned`) |
| **Commitment replay across workers/tasks** | A rival copies a victim's commitment hash (visible via `get_task`) and replays the victim's `(price, salt)` once it is revealed in another round. The hash binds the bidder account and each reveal consumes only the commitment of the task it names, so the copier never gets a bid and a reveal cannot be replayed or cross-applied. Known limit: the hash does not bind `task_id`, so reusing `(price, salt)` across rounds links them and leaks the sealed price once one round reveals; clients must use a fresh random salt per round. | `copied_commitment_cannot_be_revealed_by_another_worker`, `reveal_only_consumes_the_named_task_commitment`, `reused_salt_across_tasks_yields_identical_hash_design_limit` — `tests/test_cross_task_commitments.rs` |
| **Sealed-bid grinding (low-entropy salt)** | `get_task` exposes each commitment during the commit window; price is low-entropy and the salt is a `u32`, so a rival grinds `prices × 2^32` SHA-256 offline (100 prices ≈ 4.3e11 hashes, under a minute on one consumer GPU), learns the sealed price and commits just below it. Known limit, not fixed before the freeze: the remedy (≥128-bit salt) changes the `reveal_bid` ABI and every client; meanwhile clients should keep commit windows short and draw the full 32-bit salt from a CSPRNG. | `sealed_price_is_ground_from_public_commitment_and_undercut`, `full_salt_space_is_cheap_to_grind` — `tests/test_salt_entropy.rs` |
| **Escrow ledger drift** | The storage-reserve guard trusts a running escrow total under raw key `b"e"` (added by `post_task`, released by `attest`/`refund_expired`). If it drifted, spam could again freeze honest escrows (under-count) or honest posts be rejected forever (over-count). A seeded 120-task mixed workload (settle, attest(false), cap-overflow refund, no-bid and silent-winner refunds, tasks left Open/Closed) checks after every call that `b"e"` equals the Open\|Closed rewards and posted = paid + refunded + owed; legacy state without the key rebuilds the total by scan on the first `post_task`. | `contract/tests/test_escrow_ledger_invariant.rs` (`escrow_total_matches_open_tasks_under_mixed_workload`, `legacy_state_without_key_rebuilds_total_on_first_post`) |
| **Payee deletes its account before payout** | A winner (before `attest`) or a publisher (before `refund_expired`) deletes its account so the detached `Transfer` targets a nonexistent account. Payouts are fire-and-forget after state is final, so the settling call never reverts: the task reaches `Settled`/`Refunded` exactly once, a silent winner is still penalised, the bounced deposit returns to the contract (no yocto lost or minted; it stays as free balance), repeat settlement is rejected and the storage-reserve guard keeps admitting honest posts. | `contract/tests/test_deleted_winner_payout.rs::test_deleted_winner_payout_bounces_to_contract`, `contract/tests/test_deleted_publisher_refund.rs::test_deleted_publisher_refund_bounces_to_contract` |
| **Result substitution after delivery**: a non-winner submits a result, or the winner swaps its `result_hash` after the verifier read it, or submits before close / after settlement. | `submit_result` requires caller == winner, state `Closed`, `result_hash.is_none()` and 1..=128 B; the first hash is kept. | `test_submit_result_guards`: `only_the_winner_submits_once_and_only_while_closed`, `no_submit_after_settlement`, `no_submit_after_refund` |
| **Zero-price bid nullifies reputation**: the payout is the escrowed reward, not the bid, so revealing price 0 scores `0*(alpha+beta)/alpha = 0` for any Beta record; a worker with 1,000 failures would beat a trusted one, and on a 0–0 tie the longer failure history won the tie-break. | `reveal_bid` rejects `price == 0` (`Price must be > 0`, one `require!`, no layout change); at the floor price 1 the score is `(alpha+beta)/alpha` and reputation decides again. All swarm bids are already ≥ 1 (`swarm/test/zero_price_compat.test.js`). | `tests/test_zero_price_bid.rs`: `zero_price_reveal_is_rejected`, `minimum_price_restores_reputation_weighting` |
| **Arithmetic overflow in the reputation-weighted score**: `close_round` ranks bids by `price * (alpha+beta) / alpha`; with `u64::MAX` prices and Beta parameters near `u64::MAX` a wrapping or float score could pick the wrong winner. | Numerators are widened to `u128` and compared as exact ratios (`compare_ratios`, no division rounding); `alpha+beta` uses `checked_add` and aborts with `Reputation overflow` instead of wrapping (unreachable on-chain: ~1.8e19 settlements). Release profile keeps `overflow-checks = true`. | `tests/test_reputation_extremes.rs`: `extreme_reputations_compare_exactly_without_overflow`, `extreme_reputations_trusted_whale_wins_just_below_max`, `reputation_sum_overflow_is_rejected_not_wrapped` |
| **Wrapping or unreachable round windows**: a publisher passes `commit_len`/`reveal_len` near `u64::MAX` to wrap `commit_end`/`reveal_end` to a past height (instant close or early refund), or parks a "lure" round that never closes. | `post_task` uses `checked_add` ("Commit window overflow", "Reveal window overflow"); `refund_expired` aborts on "Refund height overflow" instead of wrapping; an unreachable round can neither close, pay nor refund, so it only locks its own publisher's escrow and other rounds settle normally. Workers should read `reveal_end` (`get_task`) before committing. | [`contract/tests/test_window_extremes.rs`](contract/tests/test_window_extremes.rs) (4 tests) |
| **Silent verifier keeps delivered work** (publisher names itself verifier): the winner submits its result, the verifier never attests, and after `reveal_end + 100` blocks `refund_expired` returns the escrow to the publisher. | Disclosed trust limit: the verifier is the trust root of each task. Bounds pinned by the test: the delivering winner is not penalised (β unchanged, only a missing result costs β), `attest` has no deadline so a late verdict still pays while nobody has refunded, and refund/attest are mutually exclusive (first one wins). Workers should only bid on tasks whose `verifier` (`get_task`) is independent of the publisher. | [`contract/tests/test_silent_verifier.rs`](contract/tests/test_silent_verifier.rs) (2 tests) |
| **Non-binding bid price (race to the floor)**: the payout is always the escrowed reward, so the revealed price is a ranking signal with no cost to the bidder; a trusted Beta(1000,1) quoting an honest 80 scores 80.08 and loses to a Beta(1,50) record bidding 1 (score 51). | Accepted design limit, documented in `RULES.md` §2 ("el pago liberado es siempre la recompensa en escrow"): bidding the floor 1 is weakly dominant, so rounds converge to price 1 where the score is `(alpha+beta)/alpha` and pure reputation ranks bids (a trusted worker at 1 beats the same record again; a Beta(1,80) record loses even against 80). Making bids binding (pay `min(bid, reward)` and refund the rest) changes the settlement path and the swarm clients, so it is not shipped before the freeze. | `tests/test_zero_price_bid.rs`: `minimum_price_restores_reputation_weighting` (rounds 4-6) |

## Reporting a vulnerability

Report security issues privately to the maintainer rather than opening a public issue.
Include the affected method, a reproduction (a failing test or a transaction trace is
ideal), and the impact. Do not disclose publicly until a fix is available.

Keep this file synchronized with the source: if a cited test is renamed or moved, update
the reference here so every link stays verifiable.
