## Commands

- `npm run verify:swarm` → everything below.
- `npm ci && npm test` → installs dependencies and runs tests (seed 42, 200 rounds, 20 workers, 5 publishers).
- `npm run sim` → writes `out/sim.json`; simulated benchmark scenario: market cost/verified (100) vs round-robin (4000).
- `npm run sandbox:round` → runs a full near-sandbox round (commit → reveal → close → submit → attest) ending in `Settled`; results saved in `out/sandbox_round.json`.
- `npm run sandbox:multi` → executes 5 real near-sandbox rounds (5 publishers + 20 workers); results saved in `out/multi_round.json`.
- `npm run client:sandbox` → worker-1 runs with a FunctionCall key limited to `register_worker, commit_bid, reveal_bid, submit_result`; output shows `OK: ... only has key FunctionCall`.
- `npm run sim:horizon` → `out/horizon.json`: market vs round-robin at 200, 1,000 and 5,000 rounds (seeds 42, 7, 1234).
- `npm run sim:multiseed` → `out/multiseed.json`: multi-seed interval (5 seeds x 200/1,000/5,000 rounds) of the simulated headline.
- `npm run baseline:compare` → `out/baseline_compare.json`: three cost-per-verified baselines on real data: the swarm's current spend ($23.57 for 386 verified = $0.0611 per verified result, 90.55% of spend unverified) vs the market's escrow rule on the same outcomes ($2.23 = 10.6x cheaper), plus the simulator's market vs round-robin governance with 95% CI.
- `npm run reproduce` (or `npm run reproduce:check` without regenerating) → regenerates `out/*.json` and checks the dataset (sha256 and outcome split), the seed-42 headline, the multi-seed interval, the horizon, that `worker_rates.json`/`workers_top20.json` are derived from the dataset, and that the dataset is actually anonymous (6/6 OK, or it fails with the reason).
- `npm run release` → `out/release/swarm-release.tar.gz`: publishable package without `.env` or `*.key` (clean secret scan) and `out/release/manifest.json` with the sha256 of every file.
- `npm run testnet:account` → testnet account from the faucet and `.env` (mode 600). `npm run testnet:deploy` → deploys the market and plays one round to `Settled` → `out/testnet_live_proof.json`.
- `npm run market:plan` → `out/market_plan.json`: deterministic preview WITHOUT network (seed 479) of the live market: 5 workers (real brains from the ledger), 8 rounds, 3 `Settled` / 5 `Refunded`, diverging Beta reputation (best worker-48 mean 0.80 → price ×1.25; worst worker-39 mean 0.25 → ×4). A judge without a NEAR account reproduces the economics with one command.
- `npm run testnet:market` → sends THOSE SAME rounds to `market.hidra-mkt-221016.testnet`: a **replay of the real ledger on the real chain**, 5 sub-accounts `worker-1..5` with a limited FunctionCall key, each with the LOCKED rate of its brain; public proof in `out/testnet_market.json` (accounts, tx hashes, states, reputations; no keys). ≤2.5 NEAR.
- `npm run verify:testnet` → re-checks WITHOUT keys and without spending (RPC reads only) every hash in `out/testnet_market.json`, the state/winner of every task (`get_task`) and the Beta reputation of every worker (`get_reputation`) on `market.hidra-mkt-221016.testnet`. Result on 13 Nov: `OK 8/8 rounds, 98 txs` (non-zero exit if anything does not match). Txs and states are compared EXACTLY; Beta reputation is append-only (it only grows with later rounds), so the frozen snapshot is validated as a **lower bound**: an impossible regression (chain below the snapshot) is flagged, never the legitimate monotonic growth from a later run.
- `npm run verify:testnet:f` → the same read-only verifier on the second run (`out/testnet_market-f.json`, rounds that start from the on-chain reputation of the first): `OK 6/6 rounds, 74 txs` (14 Nov). Both runs together: 14 rounds and 172 txs verifiable without keys.
- `npm run trace:repricing` → re-runs offline (0 NEAR) the 6 rounds of the second run with the rule `price × (α+β)/α` and checks that winner and final Beta match the chain: `OK 6/6 replay==chain`. The failing worker gets more expensive: worker-5b goes from 3× to 4× after failing round 2; worker-1 rises 1.67×→2.0× with 3 failures and drops to 1.9× when it succeeds (`out/repricing_trace-f.json`).
- `npm run testnet:costs` → measures over RPC the gas and NEAR burnt by the 98 txs (including all final receipts) and saves `out/testnet_costs.json`: 0.020573 NEAR / 229.390 Tgas in total; on average 0.002572 NEAR / 28.674 Tgas per round (13 Nov).
- `npm run adversarial:view` → RPC reads only (0 NEAR): quantifies with the `RULES.md` formula the adjusted price `(α+β)/α` of every on-chain worker and saves `out/adversarial_view.json`. 13 Nov: the failing worker (`worker-4`, α=1/β=3) carries ×4.0 vs ×1.56 for the reliable one (`worker-1`, α=9/β=5) → it must bid 2.57× cheaper to win; with α=0 it is not even eligible. In addition, the per-agent cap (`cap_per_agent`=10 NEAR, `RULES.md:33`) bounds what each identity can extract: with a 0.05 NEAR reward, at most 200 paid tasks (10 NEAR); task 201 is refunded (field `per_agent_cap_bound`). Offline test `test/adversarial_view.test.js`.
- `npm run sustain:project` → offline (0 NEAR): derives from the real evidence the on-chain coordination cost per verified result and projects it. 13 Nov: 0.002572 NEAR per result = 5.14% of the 0.05 NEAR reward it protects; at 1,000 verified results = 2.572 NEAR of gas, while escrow + reputation make each verified result 10.586× cheaper. Output `out/scale_projection.json`, offline test `test/scale_projection.test.js`. Coordination gas per result is FIXED (0.002572 NEAR), so the overhead percentage falls as the reward grows: 0.01 NEAR→25.7%, 0.05→5.14%, 0.1→2.57%, 0.5→0.51%, 1→0.26%; from a ~0.26 NEAR reward the overhead drops below 1%.

## Real dataset (anonymous)
- `data/hidra_week.jsonl`: 22,957 lines from the 360 real ledgers (`copias/*/polipasto/*/ledger.jsonl`), 196 aliases `worker-N` (one per head:model pair), 3.67 MB.
- Only these fields: `t, worker, tipo_tarea, resultado, segundos, coste_estimado` (no paths, prompts, run_id or keys).
- `resultado` = real ledger outcome: LOCKED 386 · FAILED 20,000 · 429 666 · SKIPPED 1,311 · TIMEOUT 418 · VIOLATION 150 · ERROR 26 (only LOCKED is success; see `data/hidra_week.manifest.json`).
- `coste_estimado` (USD): 0 if `cost_tier=free`; if `paid`, `segundos x 0.0002` (the ledger carries no tokens or price).
- `worker_rates.json` and `workers_top20.json`: LOCKED rates per worker derived from the dataset (196 workers, top 20 by volume); they feed the simulator, and `reproduce` re-derives them every time to detect staleness.

## Simulated benchmark scenario (seed 42, 200 rounds, 20 workers, 5 publishers)
- Market (sealed reverse auction + escrow): 4 verified, cost 400 -> 100 per verified result.
- Round-robin on the same data: 5 verified, cost 20,000 -> 4,000 per verified result (it also pays for unverified work).
- `npm run sandbox:multi`: 5 real rounds in near-sandbox, 5/5 `Settled` (`out/multi_round.json`).
- A single seed is one sample: at 200 rounds there are 1-4 verified results, so the figure is stated with an interval
  (`npm run sim:multiseed`, 5 seeds: 42, 7, 1234, 2024, 11):
  - market cost per verified result = 100 in all 5 seeds (the R12/R14 escrow only pays `Settled`; a failure is `Refunded` at no cost).
  - round-robin cost per verified result = 4,000-10,000 (mean 7,667) in the same sample, and 1 seed with 0 verified results
    still paying 20,000: simulated benchmark scenario, 40x at seed 42; the min-max across seeds is 40x-100x.
  - The min-max of 5 seeds is not an interval: each mean also carries a Student-t 95% CI
    (`resumen.<horizonte>.<clave>.ic95` in `out/multiseed.json`): market/RR cost factor 76.7x
    [30.4-122.9] at 200 rounds, 61.2x [50.9-71.4] at 1,000 and 62.0x [54.5-69.6] at 5,000; market/RR
    verified ratio 3.51x [3.13-3.89] at 5,000. With only 4-5 seeds the CI is wide: that is the honest statement.
  - The market does not verify more than round-robin at 200 rounds (ratio 0.33-0.80x): the advantage there is cost, not success.
  - With enough reputation it does: verified ratio 1.41-2.13x at 1,000 rounds and mean 3.51x [3.19-3.93] at 5,000
    (5 seeds: 3.69/3.19/3.47/3.27/3.93, `out/multiseed.json`).
  - At 200 rounds the market verifies 4 (seed 42) vs 5 for round-robin: it wins on cost (100 vs 4,000), not on volume; the volume advantage appears from 1,000 rounds.
